The progression

Learn the system, not just the prompt.

Each week adds one layer of control. Move from model behavior to grounding, orchestration, adaptation, evaluation, and safety.

Understand how LLMs work: tokens, prompting, context windows, function calling, and structured outputs. Map the modern AI stack across model providers, tools, platforms, agent skills, and vibe coding.

  • Latency budgets and cost controls
  • Reliability basics
  • Model and tool selection

Go beyond simple prompts. Ground model behavior in source material using RAG, vector databases, chunking, embeddings, retrieval strategies, and advanced context patterns.

  • Chunking and embeddings
  • Retrieval strategies
  • Advanced RAG patterns

Learn what makes a system agentic, choose architecture patterns intentionally, connect through MCP and A2A, and orchestrate stateful flows with LangChain and LangGraph.

  • Agent architecture patterns
  • MCP and agent-to-agent
  • LangChain and LangGraph

Know when fine-tuning pays off and when it does not. Work with parameter-efficient methods such as LoRA and QLoRA, then run models locally with Ollama.

  • Fine-tuning decisions
  • LoRA and QLoRA
  • Local inference with Ollama

Replace vague confidence with measured performance. Build golden datasets, analyze failures, use LLM-as-a-judge carefully, and create eval loops that catch regressions.

  • Golden datasets
  • Failure analysis
  • Production-ready eval loops

Understand the AI threat surface. Defend against hallucinations, prompt injection, and unsafe data handling with guardrails, policy controls, runtime checks, and red teaming.

  • PII and data privacy
  • Guardrails and policy controls
  • Governance and production readiness

Week 2 evaluation

Checklist to look after

We need to work on this.
ChecklistWeightWhat excellent looks like
Scope Depth10%

Sharp one-liner. Real user with quantified pain today. Knowledge corpus named specifically. Success metric is measurable (not just “works well”).

RAG architecture & retrieval design25%

Architecture diagram is clear. Chunking, embedding, and retrieval choices are justified for the corpus. Hybrid vs dense vs sparse trade-off is explicit. “I don’t know” path is designed, not hand-waved.

Implementation & demo25%

Prototype runs end-to-end on the use case. Code or n8n workflow is organized and reproducible. Citations are rendered. Loom shows happy path and at least one edge case live.

Evaluation rigor20%

Real Q&A test set exists and runs. Faithfulness and retrieval precision measured with numbers. Failures reported honestly, with a hypothesis on why and what you would fix next.

Communication & clarity10%

Documentation is scannable. Loom is well-paced and under 5 minutes. Design choices (chunking, embedding model, retrieval strategy) are explained, not just listed.

Out-of-the-box thinking10%

Bonus for going beyond the brief: a novel retrieval trick, a custom re-ranker, a clever UX touch, a creative eval setup, or an unusual corpus. Show us what makes your build different.
